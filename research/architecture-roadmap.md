# Architecture and implementation roadmap

Dated **2026-10-30**: coding first desktop agent for Windows/Linux/macOS with a small set of adjacent work tasks. This is the original research/selection baseline, not a completed implementation or paid competitor benchmark. Later engineering status owns delivery claims. Device GUI testing was deliberately deferred without blocking kernel/UI development.

The recommended mainline was C# 15/.NET 11, Avalonia, product owned state/tool contracts and replaceable official model adapters. Learn execution/interaction from Pi/Codex/OpenCode, code context from Aider and lightweight work templates from Goose, adding paper mechanisms only through separate small experiments. Reliability means actual edits/checks, retained user work, clear evidence and recoverable unknown outcomes.

Coding scope: understand/search projects, targeted bug/features, stream/cancel builds/tests with owned descendants, review actual diffs and preserve long task constraints/steering/restart state. Begin with one workspace writer; independent writing needs isolated worktrees and integration ownership. Code preview/diff/external IDE precede a full IDE. Adjacent work includes sourced document research, bounded file/CSV/XLSX transformation, simple reports/templates and controlled browser tests; full office editors, arbitrary desktop/browser session takeover, SaaS marketplace and always on personal assistance were deferred.

Separate Avalonia presentation from a local stdio Host owning Session/Run/ToolCall/Artifact/Approval/versioned events and SQLite recovery. Reconnect resumes acknowledged events rather than actions. Compare Microsoft Agent Framework against a small shared loop with the same tools/faults; do not stack MAF/Semantic Kernel/AutoGen. Reuse Microsoft.Extensions.AI/official providers, official MCP SDK and BCL JSON/cancellation/processes rather than copying entire TS dependency trees or creating a microservice per tool.

Tool contracts must specify resources, cancellation/idempotence, output budgets and acceptance. Edits compare baseline hashes before commit. Commands retain cwd/argv/start/exit/truncation/log source; local stop and remote unknown cost/outcome differ. Only confirmed idempotent actions may be retried; process separation/path checks are not an OS sandbox. Context starts with rules/tree/search/on demand reads/diff, preserving original events and whole tool groups. Candidate procedures have scope/source/version/preconditions and never silently update active skills. SQLite transactions/large artifact files and system credentials supply state without vector infrastructure by default.

UI workflow is project → goal → timeline/diff → checks → accept/continue, with visible stop/budget/model controls. Editor/terminal/WebView components require independent CJK/IME/accessibility/native library checks. Browser automation uses explicit Playwright contexts and installer/system dependency accounting, distinct from HTML preview.

The SDK baseline was **11.0.100-rc.3.26522.148**, net11.0/C# 15, RC3 Go-live rather than GA. Closed/union hierarchies help exhaustive internal states while wire DTOs stay versioned. Runtime Async/JSON/process/AOT changes require actual measurements; existing Task/cancellation/channels/source generation are not all new in .NET 11. Main app remains self contained JIT until component evidence justifies AOT; memory safety preview is not a reason for business layer unsafe code.

P0 validated platform/Host/model/file/process and MAF alternatives; P1 closed the coding loop; P2 added context/recovery/rules/limited MCP; P3 bounded work artifacts/browser; P4 optional offline skills/read only concurrency/worktrees; P5 distribution/signing/updates/recovery. P4 was not a release prerequisite. Full external desktop automation needs separate UIA/macOS Accessibility/AT-SPI/Wayland capability work.

Evaluation proposals fixed model/repository/initial user edits/OS/tools/budget/retries/network, retaining failures and family isolated holdouts. Suggested starting sizes were twelve deterministic faults, twenty development tasks and at least forty holdout tasks, not completed samples or guarantees of statistical power. Compare paired confidence intervals and clustered repeats for correctness/constraint preservation, intervention, cost per success, p50/p95 latency, cancellation/leaks/replay, GUI resource/IME/scrolling and artifact validity. BrowserGym/OSWorld/WindowsAgentArena cover specific environments, not universal desktop success. No framework/language/paper percentage was claimed as a measured product gain. Source ports require fixed commits/file scope and original notices; models/data/assets have separate licenses.
