# Research mechanisms for a coding agent

Historical literature memo dated **2026-10-30**. Conference acceptance, presentation type, publication year, source availability and successful reproduction are distinct evidence. This earlier memo used author pages for some Oral labels; the later [2026 official recheck](papers-recheck-2026.md) records stronger evidence/corrections and must be consulted rather than promoting earlier uncertainty to a current claim.

Coding references: Huxley-Gödel Machine searches coding harness variants but does not justify self rewriting production runtime; daVinci-Dev is agent native midtraining, whose trajectory quality can inform tracing but whose trained gains do not come free through an API; RepoMem localizes code using task era commit/issue/module memory and needs a frozen history boundary to exclude the target fix. Localization accuracy is not repair success.

Eight broad references were Gaia2 dynamic/asynchronous environments, OpenApps UI variation reliability, GEPA reflected prompt evolution, Speculative Actions, MemAgent RL memory, AgentFlow in the flow optimization, tau2 dual control and the observational production agents study. The original explicitly separated author Oral annotations from verified proceedings/recordings. OpenApps code/assets were not assumed permissively commercial. Simulated UI/support tasks did not prove native desktop/coding completion; an observational production survey did not causally validate an architecture.

Portable mechanisms were versioned observations, write rechecks, asynchronous completion/timeout/cancel events, UI language/layout/theme perturbations, offline text candidates with real feedback, and bounded reversible read only preparation matched before commit. MemAgent's specialized RL, AgentFlow's Flow-GRPO and JitRL's logits modulation require interfaces/training absent from ordinary hosted tool APIs. Speculative Actions' OS tuning was explicitly a lossy extension; lossless claims depend on environment and matching/side effect assumptions.

GEPA optimization needs paid or local optimizer/evaluation accounting, independent train/selection/holdout families, versioned skills, rollback and frozen active runs. ACE incremental playbook/delta mechanics were valuable without claiming main conference Oral status or full reproduction. A-Mem/APC/memory references require provenance/preconditions/revocation because generated notes can be wrong. Weak to strong LLM monitoring can fail/adversarially drift and never replaces deterministic approval or independent result checks.

The first proposed experiments were context/evidence retention, offline skill evolution and bounded read only concurrency/prefetch under the same model/tasks/budgets. Preserve all interrupted/failed runs, family isolated holdouts and independent test outcomes. Compare success/intervention/cost/latency with uncertainty, and account for extra reflection/prediction/missed branches. This memo did not run training, paper benchmarks, paid comparisons or prove C# product benefits. Reuse mature .NET runtime/network/JSON/storage/tool components and pin author source/license only if actually porting it; a paper citation is not a source port or performance result.

This English page summarizes the preserved source. [The full Chinese record](papers.zh-CN.md) retains complete historical details, examples, evidence paths and qualifications. Historical dates and test counts above are not new verification claims.
