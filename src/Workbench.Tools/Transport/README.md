# Bounded input for Microsoft JSON-RPC

`BoundedRpcPipes` is a small `System.IO.Pipelines.PipeReader` policy decorator. It rejects an unconsumed input buffer larger than **8 MiB**, completes the reader and permanently poisons that connection. `StreamJsonRpc.HeaderDelimitedMessageHandler` remains unchanged and owns all header parsing, framing, JSON decoding, IDs, dispatch and cancellation. No header, Content-Length or JSON parser is added.

The concrete missing capability is in the pinned **StreamJsonRpc 2.26.150**, source revision [`aac34050e547328910f33faeeec9eab909f3785e`](https://github.com/microsoft/vs-streamjsonrpc/tree/aac34050e547328910f33faeeec9eab909f3785e): `HeaderDelimitedMessageHandler` has no configurable maximum header/body length. It checks the textual Content-Length value only after its line is complete and can buffer an unterminated line indefinitely. Its `PipeMessageHandler` buffers a complete body for the synchronous `SystemTextJsonFormatter`, so tool DTO/output limits applied after deserialization cannot bound that allocation.

Alternatives examined were the existing handler API, `System.Text.Json` depth options and BCL `PipeOptions` pause/resume thresholds. Depth does not bound a flat string or unfinished transport header. Backpressure alone can stall a frame larger than the threshold while the reader waits for the rest; it is not a rejection policy. The decorator instead observes the BCL reader's already allocated sequence before handing it to the mature parser and throws as soon as the cap is exceeded. BCL's stream reader may read one additional ordinary buffer before the check, so this is an unconsumed-buffer limit with bounded read-ahead, not a claim of an exact total process-memory quota.

This helper is used on native-worker RPC in both directions and on language-server stdout. A violation closes the connection; worker ownership is terminated and no action is replayed. Existing LSP cancellation/error cleanup owns its server. An oversized body/header test supplies only a few KiB while declaring a multi-GiB body, proving rejection without a huge allocation. Tests also cover an unfinished header, poison permanence and successful normal messages. They validate transport resource bounds, not native OS isolation.

This is project-maintained resource policy around reused BCL and Microsoft components, not copied framing code. StreamJsonRpc's fixed package/source license remains in [LSP provenance and MIT notice](../Lsp/README.md). The limit does not claim protection against every denial-of-service vector, such as a sustained stream of small valid requests, nor does it replace execution budgets.
