# Workspace tools: components and upstream reuse

Updated 2026-10-30.

| Component | Version / source | Use and boundary |
| --- | --- | --- |
| Microsoft.CodeAnalysis.CSharp | [NuGet 5.9.0](https://www.nuget.org/packages/Microsoft.CodeAnalysis.CSharp/5.9.0), MIT, Microsoft / RoslynTeam | C# syntax parsing and source line locations. The published application carries the pinned package; it does not depend on an installed SDK's private Roslyn assemblies. No MSBuild project evaluation, source generators or repository analyzers run. |
| Microsoft.Extensions.FileSystemGlobbing | [NuGet 10.0.14](https://www.nuget.org/packages/Microsoft.Extensions.FileSystemGlobbing/10.0.14), MIT, Microsoft; pinned in the project and package lock | `Matcher.Match` filters the already validated Git/fallback inventory in memory. It does not start a second filesystem traversal or replace Git's ignore rules. The package is a Microsoft library, not an API introduced by .NET 11. |
| Git CLI | User-installed Git; [`git ls-files` documentation](https://git-scm.com/docs/git-ls-files) | Repository inventory and standard ignore rules. NUL-separated output preserves spaces/Unicode and paths are validated before use. `--full-name` is deliberately omitted so a selected subdirectory remains the path boundary. Git is invoked with an argument list, no shell, disabled fsmonitor and no inherited `GIT_*` overrides. |
| .NET BCL | Pinned project .NET 11 runtime | `Process`, redirected streams, async file I/O, cancellation, `SemaphoreSlim`, `ConcurrentDictionary`, SHA-256/`IncrementalHash`, strict UTF-8 and `Regex`. Product code owns budgets, cursors, path policy and lifecycle decisions; it does not implement a regex engine or process runtime. |
| System.Text.Json | Framework library | Source-generated metadata for command launch/persisted records (`CommandJsonContext`); the existing `Wire.Json` options serialize anonymous tool responses. This is not a claim that all tool payloads avoid reflection or that the app uses Native AOT. |

Roslyn's [syntax model](https://learn.microsoft.com/en-us/dotnet/csharp/roslyn-sdk/work-with-syntax) exposes declarations even when code has syntax errors; the tool therefore reports diagnostics and explicitly sets `semanticAnalysis: false`. A successful outline is not compilation or type-checking evidence.

Git inventory is limited to 20,000 validated files and 2,000,000 output characters, with a 20-second process deadline. Non-Git workspaces use a bounded filesystem fallback and explicitly report that gitignore was not evaluated. If a Git worktree marker exists but Git is missing or cannot inspect the repository, discovery fails instead of exposing ignored files through fallback. `pathPrefix` narrows actual traversal before the inventory budget. The GUI's existing `workspace.files` response remains a list capped at 2,000 entries.

Paged `read_file` accepts at most 16 MiB of original UTF-8 file bytes and reports the full-byte SHA-256, including a BOM. Each page contains at most 12,000 text characters; both line and character cursors are required for oversized lines, with `expectedSha256` to reject changed continuation pages. The current implementation buffers and decodes the bounded file before selecting a page; paging is not a claim of constant-memory or random-access reading. Existing write/edit limits remain 1 MiB per file.

`search_files` keeps literal, case-insensitive matching as the default and adds explicit regex/case/glob/context options. Regex uses .NET syntax and a 100 ms timeout for each matching-line operation; a timeout returns an error instead of an apparently complete partial page. This is not a 100 ms deadline for the whole search. Search visits at most 2,000 files / 32 MiB of scanned file bytes per request and reports skipped files and scan truncation; narrow the prefix when these budgets are reached. `expectedSnapshot` binds search continuation to scanned content hashes and options. `glob_files` snapshots matching names only. Neither snapshot is an atomic multi-file view or covers files omitted by the scan budget. Microsoft's [in-memory Match contract](https://learn.microsoft.com/en-us/dotnet/core/extensions/file-globbing#match-overloads) supplies glob matching; brace expansion and full ripgrep syntax compatibility are not promised.

`inspect_symbols` accepts C# text up to the existing 1 MiB file-tool limit; it outlines namespaces, types and members without descending into method bodies. Traversal is limited to 20,000 declaration nodes and depth 64; result pages contain at most 1,000 entries and signatures at most 600 characters. These are operational limits, not a benchmark claim.

Navigation responses serialize through System.Text.Json and stay within 80,000 characters by reducing whole-record pages. `nextOffset` advances only past emitted records, so Unicode escaping cannot produce invalid JSON or silently skip records. A single oversized record is reported as an error instead of returning a partially serialized result.

The provenance files link the exact upstream modules and record deliberate differences. `Workbench.Tools.csproj` copies `Licenses/**/*` into build and publish output under separate Navigation/Patch/Commands paths. Retaining Codex's original NOTICE, including its Ratatui mention, does not mean Ratatui is incorporated into this subsystem.

`apply_patch` requires hashes for every existing source and absent Add/Move destinations, preflights all edits, stages backups, rechecks before commit and attempts reverse rollback on controlled failure. BCL file operations, shared edit locks, SHA-256 and cancellation implement the integration. Limits are 64 source operations, 512 hunks, 2 million patch characters/context comparisons, 100,000 patch lines, 1 MiB per file, 8 MiB combined original/replacement bytes and 80,000 characters of result metadata checked before writing. A crash during multi-file commit may leave partial edits; this is not a power-loss-atomic transaction or a filesystem sandbox. Incomplete rollback preserves recovery files and reports failure.

`start_command` / `read_command` / `stop_command` use a hidden worker instance of the existing Host, redirected BCL streams and durable JSON/log files. Closing the owning parent pipe requests cancellation; normal cancellation and run end stop still-running commands. Commands are noninteractive, accept a configured timeout of 1–3600 seconds, retain at most 4 MiB of output and return UTF-8 byte cursors with at most 12,000 text characters per read. Pages shrink at complete scalar boundaries to stay below 80,000 serialized characters. Commands are limited to 32,768 characters and 40,000 serialized metadata characters; larger scripts belong in workspace files. Active limits are 16 commands per manager and four per workspace. Logs are bound to the chat/workspace; later turns can inspect them, but lost workers become interrupted rather than being reattached or replayed. This does not contain deliberately detached descendants or establish identical three-platform behavior. Running, interrupted or cancelled output is not successful verification; exit zero alone is not task success.

Regression entry points are [NavigationUpgradeTests](../../tests/Workbench.Tests/NavigationUpgradeTests.cs), [RepositoryNavigationTests](../../tests/Workbench.Tests/RepositoryNavigationTests.cs), [PatchTests](../../tests/Workbench.Tests/PatchTests.cs), [CommandSessionTests](../../tests/Workbench.Tests/CommandSessionTests.cs) and [EvidenceToolUpgradeTests](../../tests/Workbench.Tests/EvidenceToolUpgradeTests.cs). Test results and actual platform coverage belong in the integration report. These choices avoid introducing duplicate parsers/runtime dependencies; no measured speed, allocation, startup or code-size improvement is claimed here.
