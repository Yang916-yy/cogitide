# Background command sessions

`CommandSessions.cs` implements `start_command`, `write_command`, `read_command` and `stop_command` with ownership, log cursors, state validation and recovery. A hidden Host subprocess owns each command; parent stdin EOF cancels the shell and its process tree when the Host disappears.

Session IDs, yielding, polling, running/terminal states and bounded output are behavior references to Codex unified exec, fixed commit `788b9d7bf6e37f735647b7f84b556c2a807df4d8`. [Commands provenance](../Licenses/Commands/PROVENANCE.md) retains source mappings, Apache 2.0 LICENSE/NOTICE and deliberate exclusions. This is not a Rust runtime/sandbox port and does not invoke the Codex executable.

Execution reuses .NET `Process`, `FileStream`, `CancellationToken`, `SemaphoreSlim`, `ConcurrentDictionary`, System.Text.Json source generation and [WorkspaceService](../Workspace/README.md). [InteractiveCommands.cs](InteractiveCommands.cs) reuses **Porta.Pty 2.2.3**, the existing Desktop terminal dependency, for an actual ConPTY/Unix terminal. The fixed package revision is [`0186b604bf40161f199823fe5cdb2dfa02c37bea`](https://github.com/tomlm/Porta.Pty/tree/0186b604bf40161f199823fe5cdb2dfa02c37bea); its original [MIT license](../Licenses/Commands/Porta-Pty-LICENSE.txt) is retained. No terminal native interop, terminal emulator, process supervisor or second IPC server was introduced. Parent pipe ownership, log restoration and run ownership are project engineering additions rather than a learning algorithm.

Default commands belong to the current run. Cancellation, run completion and Host loss stop owned active commands. Explicit `lifetime: "session"` retains a development server across normal run completion until its fixed expiry, `stop_command`, chat cleanup or Host loss. The creation token still cancels it; retention never silently changes a budget or reconnects a process after restart. Timeouts are bounded to 1–604800 seconds; the model tool defaults to six hours while the direct C# API retains its prior ten-minute default. Later runs in the same chat and workspace can read retained logs and interact with session-owned commands. Run-owned input additionally requires the original run. Restart neither attaches to an old PID nor replays a command. Logs retain at most 4 MiB and use UTF-8 byte cursors. A running ID is not proof of completion. BCL process tree termination is not an OS sandbox or a guarantee about deliberately detached descendants.

`interactive: true` enables controlled UTF-8 stdin through the existing BCL execution path. `tty: true` additionally selects Porta.Pty; this is a real terminal and output can include ANSI sequences. Standard Host JSON-RPC input is never inherited. The existing worker ownership pipe carries a launch JSON line followed by bounded input JSON lines; acknowledgements use worker stdout, separate from retained command output. This extends the existing protocol instead of adding a named-pipe server. EOF on the ownership pipe still stops the command rather than merely closing command input.

Writes are serialized with one outstanding acknowledgement, at most 16384 UTF-8 bytes per call and 1 MiB per command. Each write has a five-second acknowledgement deadline (worker stream delivery is bounded to four seconds). Acknowledgement means the stream was flushed, not that the application consumed or acted on the input. Cancellation, backpressure or a lost acknowledgement stops ownership and reports an unknown input outcome; input is never replayed automatically. `closeInput` closes redirected pipe stdin and prevents later writes while preserving output collection. PTYs have no portable half-close: `closeInput` is rejected for PTYs; callers must send explicit terminal controls such as Ctrl-D when appropriate to that application, or stop the command.

[CommandInputTests](../../../tests/Workbench.Tests/CommandInputTests.cs) adds deterministic local-process fixtures for pipe Unicode/EOF, ownership, budgets, session retention/cancellation/expiry, approval registration and a real terminal round trip. Existing [CommandSessionTests](../../../tests/Workbench.Tests/CommandSessionTests.cs) retain parent loss, process tree, UTF-8 cursor and state-corruption coverage. These are functional acceptance tests, not measured research or three-platform performance claims. The final validation report records which platforms were actually exercised.

On Windows, status replacement uses BCL `File.Replace`; initial creation uses `File.Move`. Deterministic shared handle evidence and [runtime #114230](https://github.com/dotnet/runtime/issues/114230) informed the replacement. Reads retry only transient missing path/sharing errors, with cancellable total backoff of at most 310 ms. Permanent errors and corrupt state remain errors; commands are never retried. Diagnostics retain bounded stage/type/HResult without command text, paths or credentials. This does not guarantee that the path is openable at every instant of kernel replacement.

**Do not reinvent infrastructure.** Reuse this lifecycle and mature BCL/PTY components. Extensions must document source versions and cancellation, parent loss, Unicode and output budget evidence; background execution never bypasses ownership or terminal state checks.

## Pinned-runtime macOS process cleanup

The pinned .NET 11 RC macOS runtime has a documented `Process.Kill(entireProcessTree: true)` SIGSTOP/child-reaper regression: [runtime issue 131944](https://github.com/dotnet/runtime/issues/131944), [upstream backport 135409](https://github.com/dotnet/runtime/pull/135409), commit `c8b56e6c12e3010e74e1724487a65cbb1c75d0d1`. `ProcessStartInfo.CreateNewProcessGroup` is Windows-only in this SDK and cannot solve it on Unix.

Until the fixed runtime is deployed, the shared macOS stop helper uses the existing system `/bin/ps` for a bounded PID/parent snapshot and BCL single-process `Kill()` in descendants-first order, without SIGSTOP or process-group signals. Start-time checks reject recycled PID identities. Other platforms keep the existing BCL tree operation. Commands and macOS MCP clients share this helper; no second process supervisor, native interop or MCP protocol parser was added.

This is a targeted workaround for a measured runtime gap. The snapshot cannot contain new forks or deliberately detached descendants and is not an OS sandbox. Inventory/cleanup failures are reported as unverified cleanup, never successful command execution. Tests exercise owned parent/child cancellation, failing stdout/stderr retention and a subsequent fresh process to check the runtime reaper remains usable.
