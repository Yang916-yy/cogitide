# Project skill management

`SkillManagementService` adds explicit directory import, public catalog search and pinned GitHub installation to the existing [Core project skill discovery](../../Workbench.Core/Projects/README.md). All destinations are under the selected workspace's `.agents/skills`; no home configuration or globally installed skills are imported. `SkillManagementTools` exposes read-only `search_skills` and approval-required `install_skill` to the shared kernel. Desktop and remote stdio Host use the same service and protocol DTOs.

Search matches bounded metadata locally after downloading an immutable upstream source archive. The maintained default is [Anthropic's examples](https://github.com/anthropics/skills/tree/ca45fc496a3436251f191354091d557da31c15b5), pinned to `ca45fc496a3436251f191354091d557da31c15b5`. Optional `sourceId=openai-legacy` references [OpenAI's former catalog](https://github.com/openai/skills/tree/49f948faa9258a0c61caceaf225e179651397431), pinned to `49f948faa9258a0c61caceaf225e179651397431`; its upstream README now marks it deprecated. These are source labels, not vendor verification or claims that Claude/Codex-specific instructions work unchanged in Cogitide. Search supports `query`, `offset`, and `limit`. `NextOffset` is present only when another page of matching entries exists; `Truncated` retains that page-level signal. Skipped incompatible/oversized manifests and the bounded source entry cap instead set `CatalogIncomplete`, with an explanatory warning. Pagination cannot recover omitted source entries and stops when `NextOffset` is null.

`project.skills.import` takes `workspacePath` and an absolute `sourcePath` **on the connected Host**. A remote path is not a desktop upload. `skills.catalog.search` takes `query`, optional `sourceId`, `offset`, and `limit`. `project.skills.install` takes `workspacePath` and either the exact returned `skillId`, or `repository` (`owner/repository`), an immutable 40-hex `revision`, and `skillPath`. Branches, credential-bearing URLs and arbitrary archive hosts are not accepted. The selected remote directory's basename must equal its manifest name so the approval scope names the actual destination. Directory-only manual import supports a different source directory name when the manifest supplies its own valid name.

## Boundaries

Installation validates the complete selected package before creating a hidden staging directory, writes files and per-file SHA-256 provenance there, then publishes through a same-volume directory rename. Existing destinations are never overwritten. Cancellation before publication does not expose a complete-looking skill; cleanup uses checked nonrecursive deletes and preserves suspicious leftovers. `.cogitide-skill.json` records origin, pinned commit/path when present, original file hashes and the fact that scripts were not executed. Root upstream license/notice files are retained in `.cogitide-source-notices`, alongside unchanged per-skill files. Online packages require an included license file; the service does not infer rights from a repository label or a third-party notice alone.

Manual import of a previously installed Cogitide skill directory skips its old root `.cogitide-skill.json` and generates a new receipt from the files actually copied. The new receipt identifies the selected endpoint-local source directory; it does not inherit old receipt claims as verified upstream provenance. The original source receipt is left intact. Importing into an existing destination still refuses overwrite.

Copies reject path traversal, links/junctions, special ZIP entries, Git internals, alternate streams, Windows device names, ambiguous/case-colliding files, reserved provenance paths in remote archives, files above 2 MiB, packages above 256 files/16 MiB, directory depth above eight, downloads above 32 MiB, and source archives above 20,000 entries/128 MiB expanded. The manifest retains Core's 64 KiB and metadata limits. Manual imports reuse the shared [regular-file preflight](../Workspace/README.md) before opening each source file; Unix FIFO/device/socket types and Windows device entries are refused, and absence of the required system predicate fails closed. Empty directories and executable permission bits are not installed. Packages that need those features, external relative resources, Git submodules, installers or additional dependencies require an explicit separate workflow. ZIP contents remain data; no archive program, Git checkout hook, package manager, shell or package script is invoked.

Model installation uses the existing tool approval and `IWorkspacePathTool` project rule checks. A skill's instructions cannot authorize its own installation or widen permissions. Direct UI import/install requires the existing idle Host workspace admission gate, preventing races with active runs or review mutations. Existing discovery is refreshed at model request boundaries, so a newly installed valid skill can become available in the same run without replaying tools. Optional native workers execute these same tools inside their existing filesystem/network policy; denied online access fails there, with no privileged Host proxy or network fallback. Ordinary path checks and same-volume publication are application safeguards, not protection against a hostile same-user process racing filesystem changes.

## Reuse and provenance

This is project-maintained adapter code, **not** a port of either upstream install script or plugin manager. `.NET` `SocketsHttpHandler`/pooled `HttpClient` supply anonymous HTTPS, `ZipArchive` owns ZIP parsing, BCL supplies bounded streams/JSON/SHA-256/cancellation, `WorkspaceService.Resolve` supplies workspace checks, and Core's existing YamlDotNet-backed `ProjectRules.ValidateSkillManifest` supplies the single skill frontmatter parser. No second HTTP stack, YAML/archive parser, credential store, database or process runner is introduced. The missing capability was explicit package acquisition: Core discovery deliberately only reads existing project files. Fixed source/license references are packaged in [Licenses/PROVENANCE.md](Licenses/PROVENANCE.md).

`SkillManagementTests` exercises deterministic archive fixtures, import/discovery compatibility, immutable reference validation, license retention, unsafe paths/links/sizes, cancellation, overwrite refusal, approval scope, and direct Host mutation admission. These are functional checks, not evidence that an imported skill improves task success, is safe to execute, or works in every provider/runtime.
