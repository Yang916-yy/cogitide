# Session and event persistence

`SqliteSessionStore` implements `ISessionStore`: sessions/messages/checkpoints, ordered per session event append, schema versions and recovery state. Unknown newer schemas are rejected rather than overwritten by a silent downgrade.

The adapter reuses **Microsoft.Data.Sqlite 10.0.14**, SQLite transactions/WAL, parameterized commands, System.Text.Json, BCL paths/async cancellation and `SemaphoreSlim`. Versions are pinned in [the project](../Workbench.Core.csproj) and [lock file](../packages.lock.json). It is application use of a mature database, not a new storage service or a source port.

Snapshots and raw events have separate roles. A summary is a replaceable view; original messages survive. Restart must never replay a command merely because it occurs in stored text. A successful save is not task success. User code, attachments, tool output and provider state are private runtime data and must not enter Git.

This layer supplies traceable recovery to [Runtime](../Runtime/README.md) and [Memory](../Memory/README.md), without claiming a new learning algorithm. `ReadViewAsync` and `MessagesPageAsync` use SQLite JSON projection to return recent whole assistant/tool groups, with exclusive original message-index cursors. Presentation views omit image base64 bytes and opaque provider continuation state and explicitly flag that omission; source snapshots and model history remain unchanged. `EventsPageAsync` uses the existing `(session_id, sequence)` index for bounded reverse keyset selection and returns each page chronologically. `GetEventAsync` reads one exact source event. Page limits and serialized character budgets bound returned managed data; an oversized indivisible group or event reports unavailable with an unchanged cursor rather than skipping evidence. SQLite still parses the selected snapshot, and legacy `LoadAsync`, `EventsAsync` and full snapshot writes retain their compatibility costs: end to end constant memory is not claimed.

`ListAsync` projects only session metadata. Interrupted-run recovery updates status through SQLite JSON functions without materializing every conversation. `PendingInputsAsync` projects the durable steering queue using the checkpoint's applied-event watermark, so an `input.steered` notification lost after snapshot commit cannot duplicate a user instruction. Checkpointless historical records use queued/steered FIFO counts and carry an explicit legacy-recovery flag. That legacy projection cannot distinguish a lost notification from an unapplied instruction: the runtime preserves it for review and refuses automatic rehydration, directing the user to a new chat with the confirmed task. Recovery pages preserve total pending counts and reject incomplete automatic rehydration.

Schema version **2** adds nullable `sessions.message_event_sequence` without rewriting historical message/event payloads. A message-changing save records the current source-event maximum in the same SQLite transaction as its message payload. Metadata/usage-only saves retain the previous boundary: advancing it during inference would discard unfinished token deltas. A coherent `ReadViewAsync` transaction returns both the selected message projection and this cursor. Migrated snapshots retain a null cursor until their messages change; the desktop restores those messages and pending approvals but never blindly replays ambiguous historical deltas.

`EventsSincePageAsync` uses the existing journal index for count/character-bounded forward pages after that cursor. The first page captures a finite `ThroughSequence`; following pages retain that boundary even while new source events append. An indivisible oversized record reports unavailable without advancing the cursor. Latest-view recovery restores the saved message cards, applies these source pages to presentation only, then flushes live notifications using exact bounded event identities. A fully enumerated source prefix can suppress duplicates; the largest arbitrary live sequence cannot. Message/tool completion events update already restored cards. Timeline retention remains bounded and earlier message pages remain explicit historical views. This cursor does not authorize a tool, replay a command, commit partial model state or automatically answer an approval.

`StreamEventsAsync` captures the current maximum source sequence, then reads indexed forward/reverse batches with an optional event-type filter. Appends after that high watermark cannot turn a finite recovery scan into an unending stream. Readers and the store gate are released before yielding each batch; consumers may safely read exact sources or append new events. Batch collections are bounded by count and characters, while one oversized indivisible original event is still returned by streaming rather than skipped. GUI pages use explicit unavailability for such events instead.

**Do not reinvent infrastructure.** Reuse this store and SQLite transactions/indexes/migrations. A replacement needs measured bottlenecks, compatible migration, recovery tests and comparison with mature alternatives.
