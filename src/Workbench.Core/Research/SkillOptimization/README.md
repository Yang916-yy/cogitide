# Offline skill optimization: bounded GEPA and SkillOpt mechanisms

Only an explicitly started offline run optimizes one skill text. Normal chat never launches evaluations, trains weights or installs candidates. This is independently implemented C# based on paper mechanisms, without author Python code, prompts or datasets; functional fixtures do not demonstrate coding success gains.

[GEPA v2 section 3/Algorithms 1–2](https://arxiv.org/html/2507.19457v2) supplies feedback based text mutation, training improvement before selection evaluation, per task winner sets/Pareto dominance, winner weighted parent sampling, optional complementary parent merge every three rounds and final selection by mean score. Scope is one skill module and small fixed training batches, without the full compound AI scheduler or the author's system aware crossover. [SkillOpt](https://arxiv.org/abs/2605.23904) and [author guidance](https://microsoft.github.io/SkillOpt/docs/guideline.html) supply structured failure feedback and bounded edits. This project uses a stricter selection gate: higher mean and no per task regression. Slow update, meta skills, Sleep and full author runners are excluded. Sources were reviewed 2026-10-30; GEPA is fixed v2, SkillOpt's main web guidance can change. A future source port must pin the actual commit/files/changes and retain licenses.

Shared engineering adds explicit train/selection/holdout families and cross split identical payload checks via `JsonElement.DeepEquals`. Dataset authors must still detect near duplicates. Proposers only see training diagnostics. `selection_frozen` is written before baseline/selected final tests; a worse holdout result never selects another candidate. Skills have content hashes/parents/generations; manifests have hashes. Rejected candidates, raw scores, constraints, feedback and observed usage remain. Protected text/edit spans are deterministic constraints, not proof of natural language correctness.

`SkillOptimizationContracts.cs` defines tasks, candidates, evaluations, feedback, budgets/reports and generated JSON. `SkillOptimizer.cs` owns search, gates, splits, usage, final test ordering and report commits. `ModelSkillCandidateProposer.cs` reuses `IAgentModel` for one bounded `{skill, reflection}` response, without tools or implicit retries. Host supplies `ISkillCandidateEvaluator`: isolated workspace per task/candidate, frozen initial Git revision/model/validation commands, the real AgentEngine and externally checked `[0,1]` scores. The optimizer does not execute arbitrary payload commands or accept the optimized model's own success declaration.

Evaluators must honor `SkillOperationBudget` before every model call, including compaction, and report actual cumulative `SkillUsage`. Calls and cancellation deadlines are independently bounded. Missing token usage stops further work; a cost cap without pricing also stops. Observed service usage cannot undo an in flight call: an overrun is recorded as `budget_exceeded` without further requests. Unknown prices stay unknown; cancellation/errors during an unreported operation set `AllModelCallsKnown`, `AllTokenUsageKnown` and `AllCostsKnown` false. Numbers represent confirmed portions, not a universal hard cost guarantee for arbitrary evaluators.

Exports go to a new empty artifact directory: `tasks.json`, content addressed `candidates/<ID>/SKILL.md`, metadata, `report.json` and `selected-skill.md`. Existing content and linked directories are rejected; models cannot choose paths. Temporary file replacement is not a multi file power loss transaction. No partial run resume or active skill overwrite occurs; `AutomaticallyActivated` remains false.

Reuse existing model SDKs, AgentEngine, System.Text.Json source generation, SHA256, FileStream, CancellationToken, Stopwatch, LINQ and Random. No extra model client, scheduler, vector store, training framework or database is introduced. **Do not reinvent infrastructure:** identify a real gap, alternatives and validation before custom infrastructure; never bypass approval, read final answers, edit frozen acceptance or silently grow budgets.

`SkillOptimizationTests.cs` covers complementary Pareto/merge, rejection of mean improvement with per task regression, protected text, split isolation, budgets/cancellation, complete artifacts and the official OpenAI SDK/local SSE proposal contract. Host integration covers real repository execution. Neither is the authors' benchmark reproduction.
