# Context compaction, observation views and guidance

`ConversationCompaction.cs` adapts mature Pi/OpenCode cut points, structured incremental summaries, context reserve and observation clipping. Fixed commits are Pi `e7a0df27c09d11bf4161d3605246cbf57a129cb2` and OpenCode `60072747957926e7aeec7e911fe6e23abe9bf830`; exact scope and MIT notices are in [Compaction provenance](../Licenses/Compaction/PROVENANCE.md). `CompressionGuidance.cs` adds versioned guidance, deterministic observation projection and source anchors; `CompressionGuidanceOptimizer.cs` explicitly proposes and compares candidates from isolated development/selection tasks.

The research mechanism follows [ACON v3 sections 3.2–3.3/Algorithm 1](https://arxiv.org/html/2510.00615v3): separately bound history/observations and revise natural language compression guidance from original versus compressed failures. The C# implementation is independent; [author code](https://github.com/microsoft/acon), prompts, data, distilled weights and the complete two LLM compressor were not copied.

`ProjectObservations` produces bounded JSON views of supported tool results with explicit omission markers, original ToolCallId, paths/hashes/status/exit codes/cursors and head/tail observations. If required metadata cannot fit, it preserves the original observation instead of silently dropping fields. `Prepare/GenerateAsync` uses a frozen guideline for the existing model summary while the Host preserves source paths, decisions, errors and artifact metadata in a protected appendix. User instructions stay verbatim; private provider reasoning never enters summary text. Failure, cancellation and explicit intervention do not commit a checkpoint. Raw messages and events remain unchanged.

Guidance has schema/ID/revision/SHA-256; checkpoint source appendices record the exact version/hash. Research defaults off. `Research.CompressionGuidance` opts into the default guideline; `CompressionGuidancePath` selects an explicitly exported file loaded once at run start. No live task silently updates it.

Offline proposals see development failures only; paired comparison uses distinct selection IDs, never final test feedback. A candidate must preserve every baseline success and required signal, then improve successes or tie with smaller context. Calls, time, input characters and observed tokens are bounded; unknown usage is not zero cost. Anchors preserve inspectable historical snippets within Unicode safe budgets but do not prove current file validity. Character counts are proxies rather than exact tokens/prices, and reduced context may harm cache economics.

Use `CompressionGuidance.LoadAsync`, `CompressionGuidanceOptimizer.ProposeAsync` and `CompareAsync`; the caller's frozen evaluator must enforce each passed remaining token allowance before every actual model call and report cumulative inference/summary usage. `ValidateConfiguration` checks offline configuration without keys, calls or writes. Host exposes `--optimize-compression SPEC.json --output NEW_DIRECTORY --validate-only|--execute`; exports remain candidates. [verify-research.py](../../../scripts/verify-research.py) supplies deterministic integration. [ResearchCompressionTests](../../../tests/Workbench.Tests/ResearchCompressionTests.cs) covers default baseline, model guidance, raw history, Unicode, failed commits, versions, rejected proposals, split isolation, regression and budget termination.

Engineering source protection, split gates and result preservation are not proved academic novelty, success rate, cost or latency gains. Reuse `IAgentModel`, System.Text.Json generation, BCL Regex/GeneratedRegex, SHA-256, async cancellation and existing SQLite/events. **Do not reinvent infrastructure:** no additional HTTP/SSE, parser, diff engine, database, scheduler, SDK or agent runtime. Any missing capability needs alternatives/source/license evidence and fixed failure fixtures; never remove original evidence or use final tests to select guidance.
